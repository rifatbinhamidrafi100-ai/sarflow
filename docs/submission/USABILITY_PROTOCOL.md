# Test whether an investigation is understandable

Status: protocol prepared; no participants tested and no usability results claimed.

## Purpose

Test whether a reader can distinguish a real satellite observation, a numerical result and an unsupported interpretation using the focused `/study` workflow. Automated accessibility and layout tests are separate from this human evaluation.

## Procedure

Ask a few consenting people from the intended audience to try the same tasks independently. Include someone unfamiliar with SAR. Use the exact release URL and record its source version. Explain that the interface is being tested, not the participant. Do not coach participants toward a successful answer. Do not record names, audio or video without appropriate consent.

Ask each participant to:

1. State the investigation question in their own words.
2. Find the first and last displayed acquisition dates and explain whether this is a live view.
3. Open an observation receipt and identify who provided the imagery.
4. Explain whether the page establishes flooding, damage or a calibrated numerical change.
5. Identify what evidence is missing before an event interpretation can be supported.
6. Download the evidence record and locate one source and one limitation in it.

Record task start/end times only if you can measure them consistently. Note completion without help, completion with help, inability to complete and the participant's actual explanation. A wrong interpretation is an interface finding, not a user failure.

## Report honestly

Report the actual number tested, how participants were recruited, what they misunderstood, and what changed afterward. Keep quotations faithful. Do not fabricate favorable feedback, completion rates, time savings or evidence of emergency-response usefulness. Small convenience samples are formative feedback, not proof of population-wide usability.
